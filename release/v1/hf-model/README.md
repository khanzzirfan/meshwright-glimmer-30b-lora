# Meshwright (Muse Glimmer 30B)

Meshwright turns a one-line description into a low-poly 3D game asset. This repo holds two things:

1. **Meshwright v1 (GLB code track, recommended).** The model writes one self-contained Three.js HTML page that
   builds the asset from named parts, previews it and has an **Export GLB** button. The downloaded `asset.glb`
   opens in Godot, Unity and Blender, and animated requests carry their animation in the GLB. Files: `Modelfile`,
   `system_prompt.txt`.
2. **Mesh-text LoRA adapter (glimmer-v4, experimental).** An earlier approach that writes meshes as text. Files:
   `adapter_config.json`, `adapter_model.safetensors`, `loss.json`. See the section at the end.

> Built on Muse Glimmer 30B (Apache 2.0). Independent project, not affiliated with or endorsed by Meta.

## Meshwright v1

**What v1 is, precisely:** v1 adds **no new weights**. It is Muse Glimmer 30B with a tuned system prompt
(frozen as "v3" after three rounds of benchmarking) and sampling settings, packaged as an Ollama model, plus an
optional generator script that samples, validates, repairs and grounds the output. A LoRA for the GLB track,
trained on the model's own filtered outputs (the companion dataset), is planned for v2.

### Quick start (Ollama)

```bash
ollama pull khanzz_irfan/meshwright-glimmer-30b-lora:v1
ollama run khanzz_irfan/meshwright-glimmer-30b-lora:v1 --think=false "A wooden rowing boat with two oars and a lantern on the bow"
```

Save the reply's HTML block as `asset.html`, open it in a browser and click **Export GLB**.

- **Thinking off.** All results below were measured with thinking disabled (`--think=false` on the CLI,
  `"think": false` on `/api/chat`). With thinking on (the base model's default) answers are slower and untested.
- **Hardware.** The v1 tag is built on `muse-glimmer:30b-mlx` (4-bit MLX, about 19 GB, Ollama 0.32.7 or later),
  so it runs on Apple Silicon Macs. On an M3 Max (96 GB) one asset takes about 60-70 seconds.
- **Network.** The generated page loads Three.js 0.160.0 from jsDelivr, so the browser needs internet access.

To use the prompt with another runtime, take `system_prompt.txt` as the system message and sample with
temperature 0.7, top_p 0.95.

### Results

Measured on a held-out set of 48 briefs (static props, animated assets and small sets) with a headless-Chromium
validator that loads the page, clicks Export GLB and checks the file. "Assembled" is our own geometric check:
the parts touch each other as one object and it rests on the ground (no floating parts).

| Setup | Valid GLB | Assembled (of all briefs) | Samples per brief | Seconds per brief (M3 Max) |
|---|---|---|---|---|
| Single sample (`ollama run`), 4 seeds | 87.5-97.9% | 56-75% | 1 | about 60-70 |
| Generator: adaptive best-of-3 + repair + ground drop (fresh seeds) | **48/48 (100%)** | **45/48 (93.8%)** | 1.38 | 84.5 |

Limits, stated plainly:
- **Visual quality is not yet blind-rated.** An unblinded first pass rated about a quarter of valid single
  samples "good"; the rest are recognisable but plain. The generator picks by "assembled", so its 93.8% is
  partly by construction and is not a quality score.
- Simple shapes are common (for example a boat hull as one flat slab). Briefs that list concrete parts get
  better results.
- 48 eval briefs is a small set; the confidence interval on a single-sample pass rate is roughly +/-6-10 points.

### The generator (recommended)

The generator lives in the project repo, https://github.com/khanzzirfan/meshwright-glimmer-30b-lora
(`scripts/glb_generate.py`). It samples with the same prompt, validates each answer in headless Chromium, stops
at the first valid and assembled answer within 5,000 triangles (up to 3 samples), otherwise asks the model to
fix the error or reconnect floating parts, and drops the result onto y = 0.

```bash
python scripts/glb_generate.py "A stone well with a wooden roof and a bucket on a rope" --kind static --out-dir my_assets
```

### Training data for v2

[khanzzirfan/meshwright-glimmer-30b-lora-distill](https://huggingface.co/datasets/khanzzirfan/meshwright-glimmer-30b-lora-distill)
holds 463 prompt/answer rows (424 train, 39 validation) generated by this setup and filtered to valid,
assembled answers within 5,000 triangles, with all eval subjects removed.

## Mesh-text LoRA adapter (glimmer-v4, experimental)

A LoRA adapter (rank 16) that teaches Muse Glimmer 30B to write low-poly 3D assets as text meshes from a prompt.

**Status:** early research release. Training used a small set of CC0 low-poly objects (see the project repo),
so it shows that format, stopping and detail level can be learned; it is not shown to generalise to arbitrary
categories. Held-out eval loss for this run went from 0.514 to 0.216 (`loss.json`). No other quality scores are
claimed here. This adapter is not used by v1.

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import PeftModel
base = AutoModelForCausalLM.from_pretrained("meta-models/Muse-Glimmer-30B", device_map="auto", torch_dtype="bfloat16")
model = PeftModel.from_pretrained(base, "khanzzirfan/meshwright-glimmer-30b-lora")
```
